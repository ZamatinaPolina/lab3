**1 Данные и подготовка:**
Два файла с данными, для линейной регрессии Student_Performance.csv,где из 10 000 студентов 127 дубликатов - одинаковые значения по всем признакам, они не были очищены и модель обучалась на исходных данных без изменений. 
Целевая переменная - Performance Index. Extracurricular Activities нужно было перевести в число, так как линейная регрессия считает сумму w₁x₁ + w₂x₂ + … + b, где умножаются признаки на веса. Умножить слово «Yes» на число нельзя, поэтому текст нужно конвертировать в число. Yes → 1, No → 0, тк этот признак принимает 2 значения

Разбиение выборки данных для обучения и проверки модели:  80 % обучение и 20 % тест (8000 и 2000 строк, random_state=42).

Для логистической регрессии (градиентный спуск) german.csv. Необходимо исследовать признаки которые описывают 1000 объектов выборки, их 20, разделитель ;. Целевая переменная - Creditability: 700 -"1" и 300-"0", то есть классы несбалансированы. Поэтому разбиение 80/20 сделано со стратификацией: в обучении и в тесте сохраняется доля 70 % и 30 %.Порядковые коды категорий (например, цель кредита) модель воспринимает как обычные числа, что упрощение.

Масштабирование и смещение (сдвиг) данных

Каждый признак приводится к виду (x − среднее) / стандартное отклонение. Среднее и отклонение считаются только по обучающей выборке. Зачем такие действия:

Необходимо масштабировать признаки для того, чтобы привести все данные к единому масштабу и уравнять их влияние на модель(деление на отклонение). Для градиентного спуска без масштабирования для признака с большими значениями градиент будет огромный, и тот же шаг приводит к «перепрыгиванию» минимума. 

Вычитать среднее надо для того что бы  у каждого признака среднее стало равно нулю:
Смещение модели b отвечает только за средний уровень ответа: для регрессии оптимальное b равно среднему значению целевой переменной на обучении, то есть около 55 баллов. Без центрирования b и веса «тянут» друг друга, и спуск идёт по узкому овалу вместо круглой чаши, то есть медленнее.
Веса становятся сопоставимыми между признаками. Так видно, какой из признаков влияет сильнее, а какой менее сильно. Previous Scores влияет сильнее всего (17.6 баллов на одно стандартное отклонение), а Hours Studied слабее (7.4), хотя в исходных единицах вес у Hours больше (2.85 против 1.02).

Возврат в исходный масштаб. Обученные веса w и смещение b относятся к масштабированным данным. Я пересчитываю их обратно: w_исх = w / σ, b_исх = b − Σ(w · μ / σ). Тогда итоговая модель применяется к исходным признакам без дополнительных шагов. Так появилось смещение −33.92 в исходных единицах: оно «компенсирует» то, что в формуле участвуют сырые значения признаков, а не центрированные.

Для german.csv масштабирование :
Шкалы признаков сильно различаются: Credit_Amount от 250 до 18424 (стандартное отклонение около 2823), а Foreign_Worker и No_of_dependents принимают только значения 1 и 2 (отклонения 0.19 и 0.36). Без масштабирования признак суммы кредита доминирует в градиенте и спуск не сходится на нормальном шаге, поэтому каждый признак приводится опять как для лин. регрессии  к виду (x − среднее) / стандартное отклонение. Среднее и отклонение считаются только по обучающей выборке, чтобы не было утечки из теста. 


**2 Гипотезы и эксперименты;**
Для german.csv масштабирование :
Эксперимент для german.csv  подтверждает необходимость масштабирования : без масштабирования обучение логистической регрессии на german.csv не работает: при шагах от 0.1 до 1e-4 бинарная кросс-энтропия вместо снижения с 0.693 вырастает до 8–19, а ROC-AUC на тесте остаётся около 0.50–0.58 (при шаге 1e-4 равен 0.575), то есть модель не лучше случайной. С масштабированием кросс-энтропия падает до 0.482, а ROC-AUC равен 0.808. Для KNN масштабирование критично по той же причине: расстояния определяются почти только суммой кредита (ROC-AUC 0.591 против 0.741).

Для Student_Performance.csv масштабирование :
Эксперимент для Student_Performance.csv  подтверждает необходимость масштабирования: без масштабирования регрессия разошлась уже на 4–6 эпохе (шаги 0.01 и 0.001), а с ним сходится при шагах 0.01–0.5. 

Параметры обучения (пакетный GD, начальные веса == 0). Шаг и число эпох приходят из контракта (`RegressionInput`, `ClassificationInput`), используются значения по умолчанию:
| Модель | Шаг | Эпох | Функция потерь |
|---|---|---|---|
| Линейная регрессия | 0.05 | 800 | MSE |
| Логистическая регрессия | 0.1 | 1000 | бинарная кросс-энтропия, порог 0.5 |


Минимизация бинарной кросс-энтропии эквивалентна минимизации отрицательного логарифма правдоподобия (NLL) модели Бернулли с параметром p = σ(w·x + b), то есть это оценка весов методом максимального правдоподобия (MLE). Для регрессии MSE соответствует NLL.

Г1. Масштабирование необходимо для GD.**Гипотеза подтверждена**. Без масштабирования регрессия расходится уже при шаге 1e-3 (на 6-й эпохе) и 1e-2 (на 4-й), а с z-score сходится при шаге 0.01–0.5. Логистическая регрессия без масштабирования (шаг 1e-4) даёт ROC-AUC 0.575, с масштабированием 0.808.

Г2. Выбор шага. При 800 эпохах шаг 0.001 недообучается (test MSE 141.1); 0.01, 0.05, 0.1 и 0.5 дают один и тот же результат 4.0826; 1.0 расходится на 433-й эпохе. Используемый шаг 0.05 лежит в устойчивой области. Число эпох тоже важно: при шаге 0.05 за 50 эпох test MSE 4.152, за 100 уже 4.0825.

Г3. GD доходит до оптимума МНК. Подтверждена: test MSE закрытого решения (`lstsq`) 4.0826284, как и у GD, расхождение порядка 1e-15.

Г4. Собственная логистическая регрессия не хуже sklearn. Подтверждена: sklearn `LogisticRegression(C=1e6)` на тех же масштабированных признаках даёт ROC-AUC 0.8079 против 0.8081, остальные метрики совпадают.

Г5. Дерево и KNN слабее линейной модели на этих данных. Подтверждена, но с оговоркой. Для иллюстрации (оценено на test, в итоговую таблицу не попало): KNN с k = 41 даёт ROC-AUC 0.812, дерево глубины 3 даёт 0.729, KNN без масштабирования (k = 5) даёт 0.591 против 0.741 с масштабированием.

Г6. Раньше остановленный спуск обобщает лучше (иллюстрация, оценено на test). У логистической регрессии при шаге 0.1 ROC-AUC на тесте: 100 эпох 0.8246, 200 эпох 0.8161, 1000 эпох 0.8081, 5000 эпох 0.8081. После сходимости модель без регуляризации немного переобучается; ранняя остановка действует как неявная регуляризация. Из-за выбора по тесту это не использовалось для итоговой конфигурации: параметры 0.1 и 1000 заданы контрактом.
